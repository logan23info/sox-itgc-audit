Printable ITGC audit programs

Structured step-by-step test programs for each ITGC domain. Each program covers what to request, what to test, and what conclusion to draw. Print directly or reference in fieldwork.

Print-ready AS 2201 aligned 5 domain programs

Logical Access — audit program

_____________
_____________
_____________
1
Obtain user access population (IPE)
Request full user list for all in-scope systems. Validate completeness against HR headcount. Document parameters used in extract. Note: this population is IPE — validate before sampling.
AS 1105.10A
2
Test user provisioning — new users
Sample new users added during the period. For each: obtain access request, confirm appropriate approver, verify access granted matches what was requested. Test timeliness (same-day or next-business-day standard).
LA-01
3
Test user deprovisioning — terminations
Obtain list of terminated employees from HR during the period. Cross-reference to system user list. Verify access was revoked within the policy SLA (typically 24 hours). Any terminated user with active access = exception.
LA-03
4
Test periodic access review
Obtain access review certifications for the period (quarterly or semi-annual). For each: verify reviewer is appropriate (manager, not IT), review was completed on time, and any identified inappropriate access was revoked within SLA. Validate that IPE report used in the review was also validated.
LA-02
5
Test privileged access controls
Identify all privileged/admin accounts. Verify: (a) each has a named business justification, (b) privileged accounts are not used for routine tasks, (c) privileged actions are logged, (d) no shared privileged accounts exist.
LA-04
6
Test SoD conflict resolution
Obtain the SoD conflict matrix. For each open conflict: verify either (a) role was remediated, or (b) a compensating control exists and is tested. Document unmitigated conflicts as potential deficiencies.
LA-05
7
Conclude and document exceptions
Summarize all exceptions. Classify each as CD / SD / MW per AS 2201.62–.70. Refer exceptions to deficiency log. Write overall conclusion on operating effectiveness of LA controls for the period.
AS 2201.62

Change Management — audit program

_____________
_____________
_____________
1
Obtain change population (IPE)
Request all changes deployed to production during the period from the change management system. Validate population: reconcile ticket count to deployment logs. Document extract parameters. Note emergency change percentage — flag if >10%.
AS 1105.10A
2
Test standard change authorization
Select sample of standard changes. For each: verify (a) ticket created before deployment, (b) approval obtained from appropriate approver before deployment, (c) approval timestamp precedes deployment timestamp. One approval-after-deployment = exception.
CM-01
3
Test testing and UAT evidence
For the same sample: verify testing was performed in non-production environment and evidence exists. For financially significant changes: verify business user (not IT) signed off on UAT before production deployment.
CM-02
4
Test emergency change process
Select all emergency changes (or sample if >25). Verify: (a) emergency classification is justified (outage or security breach), (b) retrospective approval obtained within policy SLA (typically 24–48 hrs), (c) emergency change rate is documented and reported to management.
CM-03
5
Test developer access to production
Cross-reference the developer team list to production environment access list. Zero overlap expected. Any developer with production access = immediate exception (MW risk). Document evidence and escalate.
CM-04
6
Conclude and document exceptions
Summarize all exceptions. Any approval-after-deployment or developer prod access should be evaluated for MW. Write overall conclusion on CM operating effectiveness.
AS 2201.62

Computer Operations — audit program

_____________
_____________
_____________
1
Obtain batch job inventory
Obtain list of all financially significant batch jobs. Confirm completeness with IT and finance. This is the population — validate it as IPE by reconciling to scheduler configuration.
CO-01
2
Test batch job monitoring — success
Select sample of days during the period (25 for daily monitoring). For each: obtain the job execution log. Verify all financially significant jobs ran and completed successfully. Note any failures.
CO-01
3
Test failure response
For any failures identified: verify (a) alert was generated, (b) incident ticket was created, (c) resolution completed within SLA, (d) re-run or remediation was documented. No ticket for a failure = exception.
CO-02
4
Test backup controls
Obtain backup job logs for the period. Verify: (a) all in-scope systems backed up per schedule, (b) backup completion confirmed (not just initiated), (c) restore test performed and documented within the year with results signed off.
CO-03
5
Test DR plan
Obtain DR plan and most recent test results. Verify: (a) test was performed within the audit period or prior 12 months, (b) results are documented with RTO/RPO validation, (c) lessons learned tracked to closure. A plan without a test result is not evidence.
CO-04

Program Development — audit program

_____________
_____________
_____________
1
Identify significant implementations
Obtain list of all system implementations, upgrades, and significant configuration changes affecting financially significant systems during the period. This is the population — each item is a testing candidate.
PD-01
2
Test SDLC phase gate approvals
For each significant project: verify evidence of SDLC phase gates — requirements approval, design approval, test plan approval, go/no-go decision. Each gate requires a named approver with a date before the next phase began.
PD-02
3
Test business user UAT
For each project: obtain UAT sign-off documentation. Verify the sign-off is from a business user (finance/accounting), not IT. Verify it is dated before go-live. Verify a test script and results document exist.
PD-03
4
Test data migration reconciliation
For any project involving data migration: verify (a) pre-migration extract count, (b) post-migration load count, (c) financial balance reconciliation (key account balances agree), (d) business sign-off that data looks correct.
PD-04
5
Test post-implementation review
For significant implementations: verify a post-implementation review was performed 60–90 days after go-live. Review should assess whether designed controls are operating and whether new risks emerged.
PD-05

Journal Entry Testing — audit program

JE testing is a required fraud risk procedure under AS 2110.61, not an optional ITGC test. IPE validation is mandatory before any selection.
_____________
_____________
_____________
1
Obtain and validate JE population (IPE)
Extract all JEs for the period. Document extract parameters (date range, entity, ledger, type). Reconcile: total JE amount to trial balance; record count to GL system total. Confirm automated entries included. Any difference requires investigation.
AS 1105.10A
2
Segment the population by risk
Stratify: (a) after-hours/weekend entries, (b) period-end entries (last 3 days of month/quarter/year), (c) round-dollar or unusual amounts, (d) entries by infrequent or new preparers, (e) entries that bypass normal workflow. Document count and $ amount of each segment.
AS 2110.61
3
Test high-risk segments
For after-hours and period-end segments: test all or a large targeted sample. For each: obtain supporting documentation, verify approver is different from preparer, verify account coding is appropriate, flag any unusual descriptions or accounts.
JE-01 to JE-05
4
Test random general sample
Select a random sample from the remaining population. Apply the same testing criteria. Document results. Any entry without adequate support or with approver = preparer is an exception.
JE-06
5
Evaluate and conclude
Summarize all exceptions. Evaluate whether any indicate fraud risk indicators (fictitious entries, entries to unusual accounts, systematic patterns). Conclude on JE control environment. Document whether any exceptions require escalation per fraud reporting obligations.
AS 2110
