SOX scoping worksheet

Risk-based top-down scoping — score each system to determine if it falls in-scope for ITGC testing. Aligned with PCAOB AS 2201 Para .20–.25 and the SEC's top-down risk-based approach.

AS 2201 Para .20–.25 Interactive scoring Print-ready
PCAOB AS 2201 Para .22: The auditor must use a top-down approach, starting at the financial statement level, to identify significant accounts, disclosures, and relevant assertions — then identify the IT systems and controls that support them. Not every system is in scope — only those that could contain a material misstatement.

Step 1 — Start at FS level

Identify significant accounts and disclosures in the financial statements. Each significant account traces back to one or more business processes, which trace back to IT systems.

Step 2 — Map systems to processes

For each significant process (AP, AR, payroll, GL, etc.) identify which applications, databases, and infrastructure support it. These are your candidate in-scope systems.

Step 3 — Score each system

Score each candidate system across five risk dimensions below. High-scoring systems are in-scope. Document your rationale — auditors will scrutinize exclusions.

Scoping rules

Key scoping principles and common errors

What always requires scoping consideration

  • Primary ERP (SAP, Oracle, NetSuite, etc.)
  • General ledger and consolidation tools
  • Payroll system (if material)
  • Revenue recognition platforms
  • Treasury and cash management systems
  • Financial reporting tools (e.g. Hyperion, Anaplan)
  • Systems feeding automated application controls
  • Infrastructure hosting in-scope applications

Common scoping mistakes

  • Scoping out a system just because IT says it's "not important"
  • Forgetting upstream feeder systems (e.g. billing → AR)
  • Excluding cloud SaaS because it "belongs to the vendor"
  • Not re-scoping after a major system migration mid-year
  • Failing to document why a system was excluded
  • Scoping in everything — scope bloat exhausts the team
  • Using prior year scope without re-performing risk assessment
