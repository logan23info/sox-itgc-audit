Cloud environments

Cloud ITGC — AWS, Azure & GCP

ITGC for cloud-native environments differs significantly from on-premise. Shared responsibility, IAM complexity, infrastructure-as-code, and serverless architectures each require specific control approaches and evidence patterns.

AWS Azure GCP Shared responsibility
Critical principle: Cloud providers are responsible for security of the cloud (physical infrastructure, hypervisor, managed services). Your company is responsible for security in the cloud (IAM, configuration, application, data). ITGC testing must focus on what your company controls — not what the provider handles.
AWS

AWS key services for ITGC

  • IAM — users, roles, policies, permission boundaries
  • CloudTrail — API activity logging (the ITGC evidence source)
  • Config — configuration change tracking
  • Organizations / SCPs — cross-account access control
  • CodePipeline / CodeDeploy — CI/CD change management
  • CloudWatch — monitoring and alerting
  • Backup — managed backup with restore testing
Azure

Azure key services for ITGC

  • Entra ID (AAD) — identity, MFA, RBAC, PIM
  • Activity Log / Monitor — audit trail for all control plane changes
  • Policy — configuration enforcement and compliance
  • Management Groups — cross-subscription governance
  • DevOps Pipelines — CI/CD with approvals and gates
  • Defender for Cloud — security posture and alerts
  • Backup / Site Recovery — backup and DR
GCP

GCP key services for ITGC

  • IAM — service accounts, roles, org policies
  • Cloud Audit Logs — Admin Activity and Data Access logs
  • Asset Inventory — configuration change history
  • Organization Policies — constraint enforcement
  • Cloud Build / Cloud Deploy — CI/CD change management
  • Security Command Center — threat detection and posture
  • Backup and DR — managed backup service

Emerging focus area

Non-human identities (NHI) — the biggest cloud ITGC gap

NHI — service accounts, API keys, Lambda execution roles, managed identities — now outnumber human users by 10:1 in most cloud environments and are the fastest-growing source of ITGC deficiencies. PCAOB inspectors are increasingly flagging NHI exclusions from access reviews.

NHI types by platform

  • AWS IAM roles, Lambda execution roles, EC2 instance profiles, access keys
  • Azure Managed identities, service principals, app registrations, client secrets
  • GCP Service accounts, service account keys, Workload Identity Federation

Required NHI controls

  • Complete NHI inventory — every service account has a named human owner
  • NHIs included in quarterly access reviews (not just human accounts)
  • API keys rotated on schedule (AWS: no long-term keys; use roles)
  • Unused NHIs decommissioned within 30 days of project end
  • NHI permissions follow least-privilege — not admin or wildcard policies
